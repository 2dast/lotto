# 대시보드 및 세트 비교 보고서 재구성 — design.md

## Metadata
- 작성일: 2026-10-16
- 상태: 구현 완료 (AC-8 전체 74개 테스트는 공식 API 호출 테스트 2개를 제외하고 64개만 확인)
- 디자인 토큰 출처: 루트 `design.md` (로또 리포트 디자인 토큰, v1.0)
- 기준 브랜치: `feature/three-option-view`

## Problem
- 1안·2안·3안 예측 세트가 대시보드와 보고서에 흩어져 있고, 보고서에는 필요 없는 섹션(적중 이력, 해석 장문 등)이 많습니다.
- 사용자가 보고 싶은 것은 두 가지입니다: (1) 세 안을 한 화면에서 나란히 보는 대시보드, (2) 세 안의 조건 차이와 추천 세트만 담긴 보고서.

## Scope
- **In scope**
  - 대시보드: 1·2·3안 카드를 가로 3열로 배치 (C안)
  - 보고서: "조건 비교"와 "추천 세트" 두 섹션만 남김. 보고서 내 명칭은 "추천 세트"로 통일
- **Out of scope**
  - 예측 생성 로직, `RULES*.md` 내용 변경
  - 백테스트 섹션, 적중 이력 섹션 (보고서에서 제거)
  - 외부 데이터 수집, `data/`·`predictions/` 변경
  - 커밋·push·PR (별도 요청 시)

## User Stories
- US-1: 방문자로서, 1·2·3안 추천 세트를 한 화면에서 나란히 보고 싶습니다.
  - Given 대시보드를 열면, when 화면이 1280px 이상이면, then 세 안이 가로 3열로 보입니다.
  - Given 화면이 768px 이하이면, then 세 안이 한 열로 쌓입니다.
- US-2: 방문자로서, 세 안의 조건 차이를 표로 한눈에 보고 싶습니다.
  - Given 보고서를 열면, then "조건 비교" 표가 첫 번째 섹션으로 보입니다.
- US-3: 방문자로서, 각 안의 추천 세트를 번호 볼로 확인하고 싶습니다.
  - Given 보고서를 열면, then "추천 세트" 섹션에 안별 세트와 번호 볼이 보입니다.
- Priority: must

## Design Tokens (루트 design.md 기준)
- 색: 화면당 강조색은 `blue-500` 하나. 본문은 `grey-900`, 보조 텍스트는 `grey-700`.
- 번호 볼: 구간별 `ball-yellow`(1-10), `ball-blue`(11-20), `ball-red`(21-30), `ball-grey`(31-40), `ball-green`(41-45). 원형, 텍스트 흰색.
  - 예외: `ball-yellow`는 다크 모드에서도 글자색을 짙게 고정합니다.
- 글꼴: Pretendard Variable. 번호와 수치 표는 `tabular-nums`.
- 간격: 화면 여백 24px, 카드 간격 16px, 라벨-값 8px.
- 라운드: 카드 12px, 큰 카드 16px, 번호 볼 full.
- 보더: 1px `grey-200` 헤어라인. 그림자는 카드에만 `shadow-1`.
- 면책 문구: `footnote` 스타일(caption, `fg-tertiary`). 문구는 "본 예측은 통계적 근거가 없으며 오락 목적입니다" 톤을 유지합니다.
- 금지: 과장 카피, 그라디언트, 한 화면에 강조색 둘 이상.

## Layout

### 대시보드 (C안)
```
[top-nav: 로또 대시보드 · N회차 예측]
[요약 바: 최근 추첨 회차·날짜·1등 당첨금 · 면책 문구]
[1안 카드] [2안 카드] [3안 카드]     ← ≥768px: 3열 / <768px: 1열
  카드: 안 이름 + 한 줄 설명 + 세트 5개(번호 볼)
[최근 5회차 당첨결과]
[footnote]
```
- 카드 표시 규칙: 안 이름(`h3`), 설명(`body-2`). 규칙 파일명(`RULES*.md`)은 카드·표·제목 어디에도 표시하지 않습니다.
- 최근 5회차 목록: 회차·날짜, 번호 볼, 보너스 번호, 1등 당첨금(없으면 "정보 없음").

### 보고서
```
[헤더: N회차 예측 · 기준 데이터 회차 · 제목 "추천 세트 비교"]
[1. 조건 비교]   ← 표 (기존 표 그대로)
[2. 추천 세트]   ← 안별 세트, 번호 볼, 구간 분포 열
[footnote]
```
- 제거: 방법, 백테스트, 해석과 한계, 결론 섹션.
- "조건 비교" 표는 현재 시안 내용을 유지하되, 헤더의 파일명 `(RULES*.md)`은 뺍니다. 헤더는 "1안", "2안", "3안"만 씁니다.
- "추천 세트" 표 열: 안, 세트 번호, 번호(볼), 구간 분포(1-9/10-19/20-29/30-39/40-45).

## Responsive
- 기준 폭 768px (CLAUDE.md 기준). 루트 design.md의 640px 기준보다 엄격하게 맞춥니다.
- 표는 `.table-scroll`(overflow-x auto)로 감쌉니다. body 레벨 가로 스크롤은 금지합니다.
- 다크 모드: `prefers-color-scheme: dark`와 `data-theme`을 함께 고려합니다.

## Data Model
- 변경 없음. 기존 예측 파일(`option1`·`option2`·`option3`)과 `data/draws.json`을 그대로 읽습니다.
- 3안 `option3`는 `predictions` 파일에 없으면 빈 상태로 표시합니다.

## API / Contracts
- 변경 없음.

## Acceptance Criteria
- [ ] AC-1: 대시보드는 1·2·3안 카드를 같은 페이지에 가로 3열로 보여줍니다 (≥768px).
- [ ] AC-2: 768px 이하에서 세 카드가 한 열로 바뀌고 가로 스크롤이 생기지 않습니다.
- [ ] AC-3: 보고서에는 "조건 비교"와 "추천 세트" 두 섹션만 있습니다.
- [ ] AC-4: 보고서의 "추천 세트"는 세트별 번호 볼과 구간 분포 열을 보여줍니다.
- [ ] AC-5: 번호 볼 색은 구간 규칙을 따르고, 옐로 볼의 글자는 다크 모드에서도 짙게 보입니다.
- [ ] AC-6: "목표금액 기준 검증 전 임시 초안" 문구는 어디에도 표시되지 않습니다.
- [ ] AC-7: 면책 문구는 두 화면 모두에 있습니다.
- [ ] AC-9: 화면 어디에도 `RULES.md`, `RULES_2.md`, `RULES_3.md` 같은 파일명이 표시되지 않습니다.
- [ ] AC-8: 기존 vitest 테스트가 모두 통과합니다 (74개 기준).

## Trade-offs
- **모바일 기준 768px vs 640px**: 768px을 택했습니다. 프로젝트 `CLAUDE.md` 기준이고, 640px 기준보다 넓어서 한 열 전환이 더 일찍 일어납니다. 루트 `design.md`와 다르므로 필요하면 루트 문서도 함께 고쳐야 합니다.
- **보고서 축소**: 백테스트 근거를 빼면 "왜 무작위와 같은지"의 설명이 사라집니다. 사용자가 명시적으로 요청한 범위이므로 따릅니다. 근거는 대화 기록과 임시 결과 파일에 남습니다.

## Open Questions

- 파일명 표시는 제거하기로 정했습니다(AC-9). 확인 사항은 없습니다.
